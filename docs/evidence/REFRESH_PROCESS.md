# Updating shared portfolio evidence

Maintain facts once, then run the adapters and checks. Ordinary page use never crawls a repository or requires an external API.

1. **Candidate facts and professional work:** edit the current CV source in `src/components/pages/CV/data/common.json`. Keep exact dates, education wording, responsibilities and credential preparation states. `src/data/candidateProfile.js` derives the shared presentation from that file and holds explicit baseline/assessment instructions. Update scoped professional skill associations there only when the responsibility actually supports them. Keep overall duration, technology tenure, leadership and operating scale separate.
2. **New delivered work:** review README, manifests/lockfiles, implemented modules, migrations, provider calls, workflows, tests, infrastructure and verification records. Record inaccessible files rather than assuming content. Add one scoped record to `src/data/auditedProjects.js` with a stable ID, real route/repository, implemented technologies, contribution description, source links and a separate deployment statement. For existing audited projects, update `src/assistant/repositoryEvidence.js` and remove contradicted claims. The shared knowledge adapter feeds Assistant, Explore skills and Recruiter View; no separate project list is needed for skill eligibility.
3. **Plans and visibility:** keep unbuilt ideas in the existing concept/CV scope records, not the implemented technology list. Hide/show showcase tiles independently of implementation eligibility. A third-party fork or dependency is not a personal contribution. Confirm scoped authorship before adding it. A built adapter is distinct from a successful live integration; a deployment definition is distinct from a deployment.
4. **Learning:** add the exact earned record to `src/data/credentials.js`, with issuer, programme/course/Applied Skills type, actual completion status, certificate and curriculum description. Set `status` explicitly for incomplete records; do not label a booked exam or preparation as earned. Current CV preparation stays in the common CV source. Never infer a credential from a repository or vendor name. Curriculum descriptions supply skill associations; add category aliases to `src/assistant/taxonomy.js` where necessary.
5. **Categories and names:** use the canonical skill name throughout (for example Google Gemini). Add query aliases in `interpret.js`, category relationships in `taxonomy.js`, and missing navigation category mappings in `skillGroups.js`. Both navigation Skills and Explore derive new audited skills from these records. Do not add a disconnected Explore skill array. `professionalSkillRecords` supplies professional usage separately; training, planned scope and declarations are not upgraded to implemented projects.
6. **Freshness:** increment the evidence revision in `candidateProfile.js`. Recruiter assessment fingerprints include the shared profile, credentials, evidence and projects, invalidating old results on content changes. Regenerate the server catalogue with `node scripts/build-assistant-server.js`; dev/build also perform this step. The generated bundle is ignored by Git. Never hand-edit it.
7. **Validation:** run `npm run test:assistant`, `npm run test:recruiter`, `npm run test:refresh`, `node src/components/pages/Explore/tests/exploreIndex.test.js`, `npm run lint`, and `npm run build`. The shared refresh tests check missing project/skill mappings, canonical duplicates, planned/hidden statuses, aliases, duration and education consistency, named-tool misses, follow-ups and fingerprint invalidation. Update stale fixtures only when the evidence or explicit candidate instructions changed; retain meaningful negative and mutation cases.
8. **Visual verification:** run Vite locally and set `PORTFOLIO_TEST_URL` for `scripts/verify-evidence-refresh-browser.js` and `scripts/verify-recruiter-browser.js`. Inspect desktop/mobile Assistant answers, source disclosure, mascot, Explore search and skill dialogs, actual project links, and Recruiter overview/expanded details with strong and weak roles. Preserve the existing cream/charcoal layout; disclosure icons use unfilled chevrons. Avoid live paid provider requests during routine tests.
9. **Audit delivery:** update `repository-audit.json`, `lambda-search.json` where relevant, and `REFRESH_REPORT.md`. Record revision, files inspected, access failures, exact scope changes, checks actually run and remaining limitations. Do not silently turn an unresolved implementation source into either confirmed code or training-only experience.

The Skills menu opens the shared Explore skills experience; there is no separate standalone Skills page/data model in this repository. Project tiles also look up skill records through the same `skillIndex`.
